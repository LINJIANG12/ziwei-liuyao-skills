# 02 反推候选体系：23:00 切日与钟表窗口

> 何时读：时辰未知进入反推时（必读）。

## 15 候选结构

时辰未知时，每个输入日期生成 **15 个候选时辰**（`init` 输出）：

- 前一日 21-23 点 **亥时** 1 个（有效命盘日期 = 前一日）
- 当日 12 个地支（子=00-01 至亥=21-23）
- **次日子时** 1 个：覆盖**当日 23:00-24:00**（有效命盘日期 = 次日，日柱按次日）
- 次日 01-03 点 **丑时** 1 个（有效命盘日期 = 次日）

## 23:00 切日、无早/晚子时

- **不存在早子时/晚子时之分**：子时只有一种，当日 23:00-24:00 属于次日子时候选
- 用户钟表时间是当日 23-24 点，但排盘用次日日柱

## clockWindow：用户实际钟表出生窗口（关键）

每个候选标注 **clockWindow**（用户实际钟表出生窗口，来源日期口径），例如：

- `date:1995-03-07:hour:11:source:1995-03-08` → clockWindow `1995-03-07 21:00-23:00`（前一日亥时）
- 次子候选 → clockWindow `1995-03-08 23:00-24:00`（**这是晚上！不是次日凌晨**）

**对照出生时段一律以 clockWindow 为准，不要按十二时辰字面换算**。候选键格式：`date:YYYY-MM-DD:hour:N:source:YYYY-MM-DD`（date=有效命盘日期，hour=时辰索引，source=来源日期）。

## 已知时辰（--time）直达

用户给出了明确钟表时间时，`init --time HH:MM` 会在输出里带 **`recommendedCandidateKey`**（与钟表时间匹配的候选 key，含 `hint`）：

```bash
node scripts/ziwei-calc.mjs init --gender female --date 2004-11-05 --time 23:30
# → recommendedCandidateKey: date:2004-11-06:hour:0:source:2004-11-05（23:30 属次日子时，排盘用次日日柱）
node scripts/ziwei-calc.mjs chart --candidate-key "date:2004-11-06:hour:0:source:2004-11-05"
```

**无需在 15 个候选中手工挑**——直接用推荐 key 取盘/锁定即可。注意 23:00-24:00 的钟表时间按 23:00 切日归属**次日子时**（见上），推荐 key 会正确指向它。

## 时段对照（钟表小时口径）

| 用户说法 | 对应候选 |
|---|---|
| 清晨 0-6 点 | 当日子/丑/寅/卯时 |
| 上午 6-12 点 | 当日辰/巳/午时 |
| 中午 12-14 点 | 当日午/未时 |
| 下午 14-18 点 | 当日未/申/酉时 |
| 傍晚 18-21 点 | 当日酉/戌时 |
| 深夜 21-24 点 | 当日亥时 + 次子（23-24 点） |

**口语「晚上/夜里/半夜」是模糊记忆**：通常涵盖天黑至凌晨（约 18 点至凌晨 1-2 点都算），不要按十二时辰字面把 00-01 点子时排除出「晚上」。只排除与所说时段**明确不相容**的候选（如说晚上则排除 6-18 点白天候选），凌晨/深夜边界候选倾向保留。
