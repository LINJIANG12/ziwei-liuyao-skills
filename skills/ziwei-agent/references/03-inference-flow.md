# 03 反推完整流程

> 何时读：反推会话的每一轮（必读）。目标：通过用户人生经历逐步排除候选，锁定唯一时辰。

## 流程总览

1. **init**：`node scripts/ziwei-calc.mjs init --gender <male|female> --date <YYYY-MM-DD> [--time] [--place]` → 生成 15 候选
2. **核对候选键**：`candidates` 查看候选状态列表（键/标签/钟表窗口/状态）——核对键与剩余候选数，不要凭印象猜键
3. **逐事件核对**：用户陈述的每个带年份/月份的事件，先取该候选的流年事实再判断
4. **记录结论**：每得出一个核对结论（候选×事件/维度×吻合/矛盾）用 `record-finding` 写入
5. **排除/锁定**：按纪律执行（见 04），排除或提出锁定建议
6. **收尾**：锁定后进入正式解读（引用 07 简易知识 + 脚本实盘事实）

## 每轮对话要求

- **问题在精不在多**：每轮最多问 1-2 个，围绕关键事件（学业/事业/感情/财富/家庭变故的年份与结果）或辅助信息
- **禁止选项引导**：不要用「符合/不符合/不确定」这类选项让用户作答，用户自由回答
- **不编造**：用户未明确说出的年份、事件与吉凶不得假设，不确定时追问

## 核对工具选择

| 场景 | 工具 |
|---|---|
| 看候选状态/剩余数 | `candidates` |
| 取某候选某年的大限/流年/小限事实 | `year-facts --candidate-key --year [--solar-month]` |
| 一次对比全部候选某年差异 | `year-comparison --year` |
| 核对家庭/感情/学业等维度星曜 | `dimension-compare --palaces 夫妻宫,官禄宫` |
| 记录核对结论 | `record-finding` |
| 排除候选 | `exclude`（按纪律执行） |
| 提出锁定建议 | `lock`（等待用户确认） |

## 关键纪律（详见 04）

- 涉及「某年发生某事」必须先取流年事实核对，不得凭印象
- 涉及月份必须用 `--solar-month` 取该公历月覆盖的全部流月（通常两个月柱），不得单月采样
- 每得出结论就 `record-finding`，后续轮次直接引用，不重复核对
- 已排除候选**不再读取、引用或分析**（排除即出局）
